# AI 코딩 도구 사용 과정 증빙

과제요건 "AI 코딩 도구 사용 과정(대화 로그/스크린샷)"에 대한 증빙 자료입니다.

## 진행 단계

### 1단계 — 초기 기획 (GenSpark)

프로젝트 초반에는 GenSpark AI와 대화하며 방향을 잡았습니다. 처음 제시한
범위는 지금의 따숲보다 훨씬 컸습니다 — VB-MAPP/QABF 같은 ABA 진단 자료를
활용한 "홈 ABA 코치"(HomeABA Coach)라는 이름의, 진단→AI 처방→주별 기록→
행동기능 분석까지 갖춘 부모 코칭 서비스였습니다(`01`~`03`).

### 2단계 — 사용자 피드백에 따른 재설계 (GenSpark)

직접 사용해 본 관점에서 AI에게 피드백을 주며 방향을 좁혔습니다(`05`).
"검사지가 길면 지친 부모가 아예 접근을 못 한다", "5~6개만 체크해도 결과가
나와야 한다", "성공이 아니라 시도에 보상을 줘야 한다"는 요구를 반영해,
AI가 아래 세 가지를 서비스의 핵심 축으로 다시 설계했습니다.

1. 대시보드형 초간단 체크
2. 6문항만으로도 나오는 홈트레이닝 미션
3. 노력 보상 게이미피케이션

이때 함께 확정한 "제품 원칙"이 실제 따숲에 그대로 이어졌습니다.

| GenSpark 재설계 단계의 원칙 | 실제 따숲 구현 |
| --- | --- |
| 진입장벽 제로 — 회원가입 없음, 첫 화면에서 몇 번의 탭만으로 시작 | 랜딩에서 "회원가입 없음"을 바로 고지, 실제로 회원가입 절차 없음 |
| 개인정보(실명·생년월일·진단명·연락처·사진) 수집하지 않음, 서버 저장 안 함 | 민감정보 입력란 없음, 기록은 localStorage에만 저장 |
| 보상은 '성공'이 아니라 '시도'에 준다. 책망·압박 문구 금지 | "작게 시작해도 괜찮아요. 이미 자라고 있어요" 문구, AI 프롬프트에 "판단·훈계 금지, 먼저 공감" 규칙 |
| 전체 검사지 대신 몇 개만 체크해도 결과가 나옴 | 오늘의 체크 → 짧은 입력만으로 대시보드·AI 카드 제공 |

즉 서비스의 **이름과 세부 기능(ABA 진단 코치 → 오늘의 기분 체크)은
바뀌었지만, 이 단계에서 정한 제품 원칙은 실제 구현까지 이어졌습니다.**

### 3단계 — 실제 구현·디버깅 (범위 확정 이후)

이후 과제 범위와 일정에 맞춰 "오늘의 기분 + 한 줄 메모 → AI 공감 카드"
단일 기능(`api/generate.py`)으로 최종 구현했습니다. 실제 코드 작성과
디버깅(모델 이름 404, 응답에 섞인 추론 흔적, 타임아웃 등)은 이 단계에서
이루어졌으며, 그 과정은 [`report.md`](../../report.md) 5-6절에 상세히
기록되어 있습니다.

**참고**: 이 3단계의 AI 도구 대화 로그/스크린샷은 가족 여행 중 이동 환경에서
작업하며 별도로 저장해두지 못해, 이번 제출에는 포함하지 못했습니다. 1~2단계
GenSpark 기획 스크린샷으로 AI 활용 과정과 그것이 실제 구현으로 이어진
흐름을 증빙합니다.
